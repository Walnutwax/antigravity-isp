# Antigravity ISP

[English](README.en.md) · [发布版本](https://github.com/Walnutwax/antigravity-isp/releases)

给 Antigravity 单独配置代理，一键启动，保持系统代理不变。支持 Clash/Mihomo 订阅、带认证的远程 HTTP/HTTPS/SOCKS5 代理、链式加密落地（订阅或 VLESS Reality/TLS 中转 → 静态落地代理）以及链式三路分流，并可按需指定域名走本机网络直连，无需先手动启动通用代理客户端。

这是一个原生 macOS 启动器。安装官方 Antigravity 并填写自己的上游代理后，它会管理本地转发进程，并带着对应代理设置启动 Antigravity。

本项目是独立工具，与 Antigravity 官方没有关联。它不提供代理节点、账号或服务资格，也不承诺改变账号可用性、地区资格或服务端风控结果。

## 工作方式

默认单跳模式：

```text
Antigravity + 遵循代理设置的子进程
                │
                ▼
       127.0.0.1:17898
   本工具启动的 Mihomo（Keep-Alive 15s）
                ├── UDP → 拒绝
                ├── 自定义直连域名 → 本机网络 / 现有 VPN
                └── 其他请求 → 你的订阅节点或 HTTP / HTTPS / SOCKS5 上游
```

可选链式加密落地与三路分流模式（经 `dialer-proxy`）：

```text
Antigravity + 遵循代理设置的子进程
                │
                ▼
       127.0.0.1:17898
   本工具启动的 Mihomo（Keep-Alive 15s）
                ├── UDP → 拒绝
                ├── 出口检测 & 核心模型/AI 域名 → RELAY（订阅或 VLESS Reality/TLS）→ UPSTREAM（静态落地代理）
                ├── 自定义直连域名 → 本机网络 / 现有 VPN
                └── 其他请求 → 开启三路分流时走 RELAY，否则全部走 UPSTREAM
```

- 原生 Swift/AppKit 界面，无 Python 运行时。
- 支持上游协议、地址、端口、用户名及密码配置；密码、订阅地址与加密中转链接均保存在 macOS 钥匙串中。
- 支持链式加密落地：可将订阅节点或自建 VLESS Reality/TLS 节点作为第一跳加密中转（`RELAY`），经 `dialer-proxy` 转发至静态住宅/ISP 代理（`UPSTREAM`），减少明文 HTTP 代理长链路被重置（RST）的概率。
- 链式模式下可选开启三路分流：仅出口检测与核心模型/AI 域名经静态落地代理，自定义直连域名走本机网络，其余流量直接走加密中转节点。
- 默认开启 TCP Keep-Alive（空闲 15 秒探测、间隔 15 秒），保持长连接活跃，减少长对话与流式响应期间的空闲断连。
- 自动管理专用本地转发进程，可配置本地端口、目标应用路径和启动器打开后的自动启动。
- 支持连接测试及可选的预期出口 IP，用于核对测试请求实际看到的出口。
- 高级设置支持精确域名和域名后缀直连，默认均为空；作为普通 Dock 应用运行，使用本项目原创图标。

它不启用 TUN，不修改系统代理或全局环境变量。代理参数与环境变量只传给本启动器启动的应用及其子进程，实际范围取决于进程是否遵循这些设置。外部浏览器、已有进程、原生 TCP 的 Git SSH，以及忽略代理设置的扩展或命令行工具不在保证范围内。

出口 IP 在连接测试及启动应用前核对；未部署系统级强制阻断或持续 IP 监测。核对成功只证明测试请求当时的出口，不能证明每个应用请求的网络路径。

## 系统要求

- macOS 13 或更新版本。
- 已单独安装的官方 Antigravity 应用（“Antigravity”与“Antigravity IDE”两个版本都支持；工具会自动检测，可在“启动应用”下拉框中切换，也可手动选择其它位置的 `.app`）。
- 可用的 Clash/Mihomo 订阅或 HTTP、HTTPS、SOCKS5 上游代理（链式落地时可额外搭配订阅节点或自建 VLESS Reality/TLS 节点）。
- 首次安装代理内核时，本机网络需要能够访问 GitHub；这次下载不会通过尚未启动的本地转发。后续启动可使用已校验的本地内核。
- 从源码构建需要 Xcode Command Line Tools，使用 `xcode-select --install` 安装。

## 从源码构建

在本仓库目录执行：

```sh
./scripts/test.sh
./scripts/build.sh
open "dist/Antigravity ISP.app"
```

输出为 `dist/Antigravity ISP.app`，可将其拖入“应用程序”文件夹。构建脚本不下载代理内核、不需要 Python，也不需要代理凭据。它调用系统 Swift 编译器，使用 Swift 5 语言模式、AppKit/Cocoa 和 Security 框架。

默认按当前 Mac 的架构构建：Apple Silicon 为 `arm64`，Intel 为 `x86_64`；输出不是通用二进制。CI 分别使用 GitHub 的 `macos-15` 和 `macos-15-intel` 运行器，测试后生成对应架构的 ZIP 和 SHA-256 文件。

当前构建仅使用本地临时签名（ad-hoc），没有 Developer ID 签名或 Apple 公证。下载的构建可能被 Gatekeeper 拦截。确认来源和内容可信后，可按 macOS 提示在“系统设置 → 隐私与安全性”中使用“仍要打开”；也可以自行审阅并从源码构建。

## 配置与使用

1. 首次使用先点击“安装代理内核”，等待固定版本的 Mihomo 下载并通过校验。这一步使用本机当前网络访问 GitHub。
2. 在“启动应用”中选择要启动的版本：工具会自动列出已安装的 Antigravity / Antigravity IDE（含版本号）；未自动检测到时点“选择…”手动指定 `.app`。
3. 在“代理来源”选择“订阅链接”或“手动代理”：
   - **订阅单跳**：粘贴 Clash/Mihomo 订阅地址，点“刷新节点”后在“节点”中快捷切换。
   - **订阅链式落地**：在订阅模式下勾选“链式落地：经订阅节点中转至下方静态代理（dialer-proxy）”，并在下方填写静态落地代理。
   - **手动单跳**：选择协议并填写服务器、端口及认证信息（或点“从剪贴板导入”）。
   - **VLESS 中转链式落地**：在手动模式下勾选“启用加密中转节点（VLESS Reality / TLS → 下方静态代理）”，粘贴 `vless://` 中转链接并填写下方静态落地代理。
4. 启用任一种链式模式后，可按需勾选“链式三路分流：仅模型/AI 域名走落地代理，其余流量走中转节点”。
5. 保留默认本地端口 `17898`，或选择其他未被占用的端口；可选填预期出口 IP（留空时仅展示实际出口）。
6. 如需让特定本地或私有网络域名直连，在高级设置中填写直连域名，详见下节；不需要时保持为空。
7. 保存配置并测试连接，然后通过启动器启动 Antigravity。

如果 Antigravity 已在运行，应先正常退出，再通过启动器启动，使新进程获得代理设置。“自动启动”指打开本启动器后自动启动代理和目标应用，不会将应用添加到 macOS 登录项。

通过启动器启动 Antigravity 后，可在“高级设置”修改两个直连域名字段并点击“应用分流”。启动器先验证候选配置，再保存列表并请求同一个代理进程重载。新规则用于后续连接。已经建立的连接可能继续沿用原路由，必要时重新打开页面或重连。修改上游代理、链式模式、预期出口 IP 或监听端口，需要停止后再配置。

不要将含有代理地址、用户名、密码、订阅地址或节点链接的截图和日志直接提交到公开 Issue。订阅地址和中转链接通常等同于访问凭据。

## 订阅与节点快捷选择

“代理来源”选择“订阅链接”后：

1. 粘贴完整的订阅地址，例如 `https://feed.example.com/c/<id>`。含访问令牌的地址优先使用 HTTPS，跳转目标须使用 HTTPS。
2. 点“刷新节点”。本工具会下载订阅、读出节点列表，并在“节点”下拉框中列出。
3. 在“节点”中选择一个节点，或保留“自动选择（延迟最低）”，然后测试或启动。自动选择可随测速结果切换节点。需要固定出口时，选择指定节点并填写预期出口 IP（或配合链式落地指向固定静态代理）。启动时会保存选择，下次打开仍可看到上次读取的节点列表。

订阅能力范围：

- 支持 Clash/Mihomo YAML 订阅，包括整体被 Base64 编码的 YAML。
- 不支持仅含节点链接（`vmess://`、`ss://` 等）或 SSR/V2Ray 原始列表的订阅；这类内容会明确报错，不会被当作可用节点。
- “测试连接”和“启动”会复用有效期内的订阅缓存，“刷新节点”会重新下载。运行中的会话使用启动时的节点列表。
- 订阅地址保存在钥匙串（account 为 `subscription`）；读到的节点名称保存在专用目录的 `subscription-nodes.json`（权限 `0600`，只写入订阅地址的指纹而不是地址本身，避免订阅令牌落盘）。
- “刷新节点”期间“停止”按钮会变成“取消刷新”，可以中断下载。

下载路径说明：订阅由本工具用 `curl` 下载后再交给内核，而不是让 Mihomo 在内核里自行下载。这样在内核直连 TLS 被网络卡住时仍可改用下方的手动代理下载；直连失败时，勾选“通过下方手动代理下载订阅（本机直连失败时）”并填写一个可用代理即可。

下载与检查速度：

- 订阅下载使用 3 路并发、优先 IPv4 的方式，单轮失败会自动再试一轮；缓存未命中时更快收敛。
- 成功下载的订阅会缓存 10 分钟（私有 `0600` 文件，按订阅地址指纹校验；缓存内容含节点配置，仅保存在本机，不进入仓库）。再次点“测试连接”或“启动”会直接复用缓存。
- 打开工具时，如果缓存缺失或过期，会在后台预取一次订阅。
- 出口 IP 检查使用 4 个检测地址并发探测，状态栏显示本次耗时。

## 链式加密落地与三路分流

如果静态住宅/ISP 代理本身仅提供明文 HTTP 端口，直接跨境连接容易出现连接重置（RST）或延迟抖动。可以通过以下任一方式在前面叠加一层加密中转（`RELAY`），由 Mihomo 通过 `dialer-proxy` 经中转拨号连接静态落地代理（`UPSTREAM`）：

- **订阅节点中转**：适合已有 Clash/Mihomo 订阅的用户。在“订阅链接”页勾选“链式落地”，并在下方填写静态落地代理信息。
- **自建 VLESS Reality / TLS 中转**：适合有自建 VPS 中转的用户。在“手动代理”页勾选“启用加密中转节点”，粘贴完整 `vless://` 链接（支持 `type=tcp` 且 `security=reality` 或 `security=tls`）。中转链接单独保存在钥匙串（account 为 `relay-uri`），不写入明文 `settings.json`。

自建 Xray VLESS Reality 服务端可参考仓库内的去敏模板 [examples/xray-reality-server.example.json](examples/xray-reality-server.example.json)，部署时需特别注意两点兼容性：

- **Xray 版本**：与当前固定内置校验的 Mihomo `v1.19.34` 配合时，服务端建议使用 **`Xray-core v26.6.27`**。`v26.7.11` 及之后版本在 Reality 握手阶段强制校验较新的 `minClientVer`，会拒绝当前版本 Mihomo 客户端。
- **关闭入站 Sniffing**：服务端入站配置必须设置 `"sniffing": {"enabled": false}`。若开启 HTTP/TLS 探测，服务端会改写第二跳明文 HTTP `CONNECT` 代理的目标地址，导致链式落地超时。

勾选“链式三路分流”后，Mihomo 规则变为：

1. UDP 请求使用 `REJECT`。
2. 出口检测域名（`api.ipify.org`、`www.cloudflare.com`、`api.myip.com`、`ifconfig.me`）与核心模型/AI 域名（Google、Antigravity、Anthropic、OpenAI 等）固定走 `UPSTREAM`（链式静态落地）。
3. 高级设置中明确配置的直连域名走 `DIRECT`。
4. 其余流量走 `MATCH,RELAY`（直接走加密中转节点，不经过静态落地代理）。

## Codex Theme、汉化与会话统计

在“启动应用”中选择 Antigravity App，勾选“启用 Codex Theme、汉化和会话统计”，再通过本工具启动。主题默认关闭，启用时需要安装 Node.js 22.13 或更新版本。自动检测不到时，在启动器里填写 `node` 可执行文件的完整路径。Antigravity IDE 可继续使用代理功能。

启用后，输入框下方会显示首字等待时间、上下文占用和输出速度。悬停统计栏，在“当前上下文”旁可以看到本会话已完成的压缩次数，包括正文已清理的历史压缩记录。

主题由启动器管理，只连接这次启动的 Antigravity 的本机调试端口，并以只读方式读取本机的会话统计。它会随会话退出。版本和授权来源见 [第三方声明](THIRD_PARTY_NOTICES.md)。

## 自定义直连域名分流

高级设置提供两个默认留空的字段，均支持逗号、空格或换行分隔多个域名：

| 字段 | 设置键 | 示例与匹配范围 |
| --- | --- | --- |
| 精确直连域名 | `directDomains` | `portal.example.com`，仅匹配该域名 |
| 直连域名后缀 | `directDomainSuffixes` | `internal.example.org`，匹配该域名及其子域名 |

只填域名，不含协议、路径或通配符。仅添加你明确需要直连的本地或私有网络域名；保存时会拒绝已知模型服务域名的直连配置。该校验并不包含所有当前及未来服务域名，不能作为完整的网络隔离保证。

默认单跳模式（或链式模式未开启三路分流）下，进入本地 Mihomo 的请求按以下顺序匹配：

1. UDP 请求使用 `REJECT`。
2. 出口检测域名 `api.ipify.org`、`www.cloudflare.com`、`api.myip.com` 和 `ifconfig.me` 强制使用 `UPSTREAM`，不受直连配置影响。
3. 明确配置的精确域名和域名后缀使用 `DIRECT`。
4. 其余请求使用 `MATCH,UPSTREAM`；上游连接失败时不回退到 `DIRECT`。

直连域名使用本机系统 DNS 和当前本机网络（包括已连接的私有 VPN）。CLI 或工具只有遵循启动器传入的代理设置，请求才会进入这些分流规则；分流不会替代登录、认证或访问权限。

让模型读取本地或私有网络内容时，通常是本机工具先经直连路径取得内容，再通过上游代理将相关内容发送给模型服务。这是两条网络路径，直连配置并不意味着相关内容只留在本机。

## 数据与内核

设置与运行文件位于当前用户的专用目录：

```text
~/Library/Application Support/AntigravityISP/
```

敏感凭据使用 macOS 钥匙串保存（service 为 `io.github.antigravity-isp.proxy`）：

- `default`：手动上游/落地代理密码
- `subscription`：Clash/Mihomo 订阅地址
- `relay-uri`：VLESS Reality/TLS 加密中转链接

运行期间 Mihomo 需要读取代理认证信息，因此会生成权限为 `0600` 的临时配置；订阅模式下载的节点 YAML 也存放在该临时运行目录中。异常退出后的残留进程与临时配置会在下次启动时自动清理。正常停止或退出时删除这些临时配置；强制终止或系统崩溃可能中断退出清理。读到的节点名称列表保存在 `subscription-nodes.json`（权限 `0600`，不含订阅凭据）。

点击“安装代理内核”后，本工具从 [Mihomo 官方 v1.19.34 发布页](https://github.com/MetaCubeX/mihomo/releases/tag/v1.19.34)获取与机器架构对应的固定版本，并按代码中固定的 SHA-256 校验下载内容。内核存放于上述目录的 `bin/` 中。仓库和生成的 `.app` 均不包含 Mihomo 二进制，也不包含真实代理凭据。

## 常见问题

**首次下载失败**：检查当前网络是否能访问 GitHub 官方发布资源，再重试。校验不匹配的内核不会被使用。

**订阅获取失败**：若提示直连失败，勾选“通过下方手动代理下载订阅（本机直连失败时）”并填写一个可用代理。确认订阅地址有效，返回 Clash/Mihomo YAML。

**订阅节点无法连通**：“自动选择”依赖内核测速，个别节点被目标网站拦截时仍可能失败。点“刷新节点”后手动换一个节点再测试。

**自建 VLESS Reality 中转无法握手或链式超时**：确认服务端 Xray 版本固定在 `v26.6.27`（`v26.7.11+` 与 Mihomo `v1.19.34` 存在 Reality `minClientVer` 握手不兼容），且入站 `"sniffing": {"enabled": false}` 已关闭。

**本地端口已占用**：本工具会先清理自己上次异常退出（崩溃、强制退出）遗留的内核进程和临时配置，因此正常情况下重试即可。仍提示被占用时，说明端口被其他程序占用：选择其他未被占用的本地端口并保存，然后重新启动代理。

**上次异常退出后连不上**：本工具在每次启动前会结束自己遗留的 Mihomo 进程、删除残留的临时配置（其中含凭据）并释放端口，无需手动处理；若仍有问题，退出本工具后重新打开再测试。

**强制退出后仍有代理进程或临时配置**：强杀或系统崩溃可能留下本工具启动的代理进程和临时配置。确认进程的可执行文件位于本工具的专用目录后再处理；本工具不会仅按端口号自动杀死进程。处理前保留其他代理客户端和不相关进程。

**出口 IP 与预期不同**：核对上游配置和代理服务的出口策略。某些服务会轮换出口 IP；预期 IP 应与所用服务一致。

**连接测试成功，但应用仍无法使用**：检查应用是否通过启动器重新启动，以及失败请求是否来自外部浏览器、扩展或独立工具。代理连通不等于账号或服务资格验证成功。

**自定义直连站点或私有工具无法访问**：先确认本机已连接对应本地网络或 VPN、系统 DNS 可以解析目标域名并已完成所需认证，再检查直连域名是否匹配，以及发起请求的工具是否遵循代理设置。

## 卸载

先停止转发并退出启动器，再删除 `Antigravity ISP.app`。如需清除启动器保存的数据，删除 `~/Library/Application Support/AntigravityISP/`，并在“钥匙串访问”中删除服务为 `io.github.antigravity-isp.proxy`、账户为 `default`、`subscription` 和 `relay-uri` 的条目。

这些是本工具专用的数据。保留官方 Antigravity 应用及其用户数据。
